### O que entregar

Solicitação com motivo, resolução desejada e itens; análise, aprovação/recusa, postagem reversa, recebimento, reembolso e conclusão, com histórico (origem e autor). Parâmetros de `ConfiguracaoLoja` (D8). Fluxo:

SOLICITADA -> EM_ANALISE -> APROVADA | RECUSADA ; APROVADA -> POSTAGEM_REVERSA -> RECEBIDA -> REEMBOLSADA (só REEMBOLSO) -> CONCLUIDA ; RECEBIDA -> CONCLUIDA (TROCA, REPARO). Pedido vai a EM_DEVOLUCAO ao aprovar e a DEVOLVIDO ao concluir um reembolso. A solicitação também grava histórico (sem status anterior, origem MANUAL, autor = cliente). Transição inválida -> 409 (D30).

### Contrato de API

Convenções gerais (paginação, `idXxx`, status `{id, nome}`, erros Problem) em [`docs/API.md`](https://github.com/DaviRSuassuna/droneshop/blob/develop/docs/API.md). Rotas do admin exigem token de administrador com permissão no módulo (#4, #5); rotas `/conta` exigem cliente logado.

```
GET /status-devolucao -> 200 [ 8 itens ] ; GET /resolucoes-devolucao -> 200 [ REEMBOLSO=1, TROCA=2, REPARO=3 ]

POST /conta/devolucoes { "idPedido": 9, "idResolucao": 1, "motivo": "Arrependimento",
                         "itens": [ { "idItemPedido": 15, "quantidade": 1 } ] } -> 200 devolução SOLICITADA
-> 409 pedido não ENTREGUE
-> 400 errors[].field = "idPedido"  fora do prazo de arrependimento contado da entrega (RN09)
-> 400 errors[].field = "itens"     item de outro pedido ou quantidade acima da comprada
GET /conta/devolucoes, GET /conta/devolucoes/{id} -> do próprio cliente

GET /admin/devolucoes?idStatus= -> PageResponse ; GET /admin/devolucoes/{id} (com histórico)
PATCH /admin/devolucoes/{id}/status { "idStatus": 3, "observacao": "..." } -> 204 | 409
   RECEBIDA gera MovimentoEstoque DEVOLUCAO de cada item (origem MANUAL, autor do token)
   REEMBOLSADA gera Estorno do valor dos itens no pagamento vigente (#36)
```
