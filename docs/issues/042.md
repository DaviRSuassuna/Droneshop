### O que entregar

Preferência por tipo (`MARKETING`, `CARRINHO_ABANDONADO`, `NOVIDADES`); marketing exige opt-in e todo e-mail de marketing leva link de descadastro com token. Transacional sempre sai. Inclui o e-mail de recuperação de carrinho abandonado (disparado pela rotina da #24 para quem tem opt-in).

### Contrato de API

Convenções gerais (paginação, `idXxx`, status `{id, nome}`, erros Problem) em [`docs/API.md`](https://github.com/DaviRSuassuna/droneshop/blob/develop/docs/API.md). Rotas do admin exigem token de administrador com permissão no módulo (#4, #5); rotas `/conta` exigem cliente logado.

```
GET /conta/preferencias-notificacao -> 200 [ { "tipoNotificacao":"MARKETING","habilitado":false } ... ]
   padrão: tudo desabilitado (opt-in, RN10)
PUT /conta/preferencias-notificacao [ { "tipoNotificacao":"MARKETING","habilitado":true } ] -> 204
-> 400 errors[].field = "tipoNotificacao"  tipo inexistente ou transacional
GET /descadastro/{token} (público) -> 200 { "tipoNotificacao","habilitado": false } | 404
Rotina carrinhos-abandonados: cliente com CARRINHO_ABANDONADO habilitado recebe o e-mail
com link /descadastro/{token}; sem opt-in, nada é enviado
```
