### O que entregar

Carrinho identificado por `tokenSessao` (header `X-Carrinho-Token`), sem login; vinculado ao `PerfilCliente` ao autenticar. Itens sempre por produto (D40), com `precoUnitarioMomento` (atualizado se o preço mudar enquanto o carrinho está ATIVO). Estados ATIVO, ABANDONADO, CONVERTIDO, EXPIRADO. Rotina `carrinhos-abandonados` marca ABANDONADO após `aeria.carrinho.abandono-horas` (padrão 24) sem alteração (D33).

### Contrato de API

Convenções gerais (paginação, `idXxx`, status `{id, nome}`, erros Problem) em [`docs/API.md`](https://github.com/DaviRSuassuna/droneshop/blob/develop/docs/API.md). Rotas do admin exigem token de administrador com permissão no módulo (#4, #5); rotas `/conta` exigem cliente logado.

```
GET /status-carrinho -> 200 [ ATIVO=1, ABANDONADO=2, CONVERTIDO=3, EXPIRADO=4 ]

POST /carrinho  (público) -> 200 { "token": "uuid", "status": {...}, "itens": [], "subtotal": 0,
                                   "desconto": 0, "total": 0, "cupom": null }
GET /carrinho   (header X-Carrinho-Token) -> 200 carrinho | 404 token desconhecido
POST /carrinho/itens { "idProduto": 31, "quantidade": 2 } -> 200 carrinho
   item do mesmo produto soma a quantidade
-> 400 errors[].field = "idProduto"  produto não ATIVO (RN17)
-> 400 errors[].field = "quantidade"  menor que 1
-> 409 quantidade acima do disponível
PATCH /carrinho/itens/{id} { "quantidade": 3 } -> 200 carrinho ; DELETE /carrinho/itens/{id} -> 200 carrinho
Item: { "id","produto":{"id","sku","nome","slug"},"quantidade","precoUnitario","subtotal" }

POST /carrinho/vincular   (cliente logado + header) -> 200 carrinho do cliente
   o cliente sem carrinho ATIVO herda o anônimo; com carrinho, os itens são somados
   e o anônimo vira EXPIRADO. POST /auth/login com o header faz o mesmo sozinho (RF17).
GET /conta/carrinho (cliente logado) -> 200 carrinho ATIVO do cliente (cria vazio se não houver)

POST /admin/rotinas/carrinhos-abandonados?referencia=2099-01-01T00:00:00 -> 200 { "processados": n }
```
