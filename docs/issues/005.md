### O que entregar

Perfil 0..1 do usuário com `papel`. Permissões (ver, editar, excluir) por módulo, geradas a partir do papel ao criar o perfil e ajustáveis por usuário.

Permissões padrão por papel:

| Papel | Ver | Editar | Excluir |
|---|---|---|---|
| ADMIN | todos | todos | todos |
| OPERADOR | todos | ESTOQUE, PEDIDO, DEVOLUCAO | nenhum |
| CATALOGO | todos | CATALOGO, ESTOQUE | CATALOGO |
| ATENDIMENTO | todos | ATENDIMENTO, DEVOLUCAO | nenhum |
| SOMENTE_LEITURA | todos | nenhum | nenhum |

Cada rota do admin pertence a um módulo: `GET` exige ver, `POST`/`PUT`/`PATCH` exige editar, `DELETE` exige excluir. Marca, categoria, subcategoria, fornecedor e produto são do módulo `CATALOGO`; usuários e configuração, de `ADMINISTRACAO`.

O admin cria o usuário com senha provisória (D35); o convite por e-mail entra com a #33. Se o e-mail já é de um cliente, o perfil administrativo é **acrescentado** à conta existente (a senha do corpo é ignorada); é assim que um usuário fica com os dois perfis (#20).

### Contrato de API

Convenções gerais (paginação, `idXxx`, status `{id, nome}`, erros Problem) em [`docs/API.md`](https://github.com/DaviRSuassuna/droneshop/blob/develop/docs/API.md). Rotas do admin exigem token de administrador com permissão no módulo (#4, #5); rotas `/conta` exigem cliente logado.

```
GET /papeis-administrativos     -> 200 [ { "id": 1, "nome": "ADMIN" }, ... 5 itens ]
GET /modulos-sistema            -> 200 [ { "id": 1, "nome": "CATALOGO" }, ... 8 itens ]
GET /admin/papeis/{idPapel}/permissoes-padrao
-> 200 [ { "modulo": {"id":1,"nome":"CATALOGO"}, "podeVer": true, "podeEditar": true, "podeExcluir": true }, ... ]

POST /admin/usuarios
{ "nome": "Marcos Rocha", "email": "marcos@aeria.com.br", "senha": "provisoria123",
  "idPapel": 3, "ativo": true,
  "permissoes": [ { "idModulo": 2, "podeVer": true, "podeEditar": false, "podeExcluir": false } ] }
  (permissoes é opcional: sem ela, vale o padrão do papel; com ela, só os módulos informados mudam)
-> 200 { "id": 7, "nome": "...", "email": "...", "ativo": true,
         "papel": {"id":3,"nome":"CATALOGO"},
         "permissoes": [ { "modulo": {...}, "podeVer": .., "podeEditar": .., "podeExcluir": .. } x 8 ] }
-> 400 errors[].field = "email"   e-mail inválido ou que já tem perfil administrativo
   e-mail de cliente: acrescenta o perfil administrativo à conta (senha ignorada)
-> 400 errors[].field = "senha"   menos de 8 caracteres
-> 400 errors[].field = "idPapel"

GET /admin/usuarios?nome=&idPapel=&page=&pageSize=   -> 200 PageResponse
GET /admin/usuarios/{id}                              -> 200 | 404
PUT /admin/usuarios/{id}   (mesmo corpo, senha opcional) -> 204 | 404
   Usuário não exclui; desativa com "ativo": false.
   Ninguém desativa nem rebaixa o próprio usuário -> 409

Falta de permissão -> 403 /errors/forbidden
```
