### O que entregar

Cada login cria uma `SessaoUsuario` (id da sessão no claim `sid` do JWT). Quem tem os dois perfis escolhe com qual entrar; a escolha fica em `perfilAtivo` e vai no claim `groups`. Sessão revogada ou expirada não autentica, mesmo com JWT ainda válido.

### Contrato de API

Convenções gerais (paginação, `idXxx`, status `{id, nome}`, erros Problem) em [`docs/API.md`](https://github.com/DaviRSuassuna/droneshop/blob/develop/docs/API.md). Rotas do admin exigem token de administrador com permissão no módulo (#4, #5); rotas `/conta` exigem cliente logado.

```
POST /auth/login  (usuário com perfil de cliente e administrativo)
-> 200 { "token": "...", "perfis": ["CLIENTE","ADMINISTRATIVO"], "perfilAtivo": null,
         "escolherPerfil": true }
   Com esse token só /auth/perfil-ativo, /auth/me e /auth/logout funcionam (demais -> 403).
   Usuário com um perfil só: "perfilAtivo" já vem preenchido e "escolherPerfil": false.

GET /perfis-ativos -> 200 [ CLIENTE=1, ADMINISTRATIVO=2 ]
POST /auth/perfil-ativo { "idPerfilAtivo": 2 }
-> 200 { "token": "...novo...", "perfilAtivo": "ADMINISTRATIVO", "escolherPerfil": false }
-> 400 errors[].field = "idPerfilAtivo"   perfil que o usuário não tem

GET /conta/sessoes -> 200 [ { "id", "perfilAtivo": {...}, "dataCadastro", "expiraEm", "atual": true } ]
   só sessões não revogadas e não expiradas do próprio usuário
DELETE /conta/sessoes/{id} -> 204 | 404 (sessão de outro usuário)
POST /auth/logout -> 204 (revoga a sessão atual)
Token de sessão revogada -> 401
```
