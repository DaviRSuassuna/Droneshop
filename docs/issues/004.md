### O que entregar

Conta única de login. `nome` (D35), `email` único (guardado em minúsculas), `senhaHash` (BCrypt, opcional para contas só-Google), `emailVerificado`, `ativo`. Login emite JWT (`quarkus-smallrye-jwt`) com o id do usuário em `sub`, o e-mail em `upn` e os perfis em `groups`.

A partir desta issue, as rotas do admin exigem token de usuário com perfil administrativo. A checagem fina por módulo vem na #5; aqui basta ter `PerfilAdministrativo`. Rotas públicas continuam abertas: `/estados`, `/municipios`, `/ceps`, `/status-*` e as demais rotas de enum, `/auth/login`, `/loja/*` e `/webhooks/*`. Os serviços falsos que só existem em `src/test` (`/viacep-falso`, `/mercadopago-falso`, `/frete-falso`, `/resend-falso`, `/google-falso`) também ficam abertos: proteja as rotas do admin por anotação no resource, não por uma regra que feche tudo.

`import.sql` cria o administrador semente `admin@aeria.com.br` / `aeria123` com papel `ADMIN` (D25). Os testes já entregues usam `testes/Api.java`, que passa a entrar com esse usuário sozinho: nenhum teste `base` precisa mudar.

### Contrato de API

Convenções gerais (paginação, `idXxx`, status `{id, nome}`, erros Problem) em [`docs/API.md`](https://github.com/DaviRSuassuna/droneshop/blob/develop/docs/API.md). Rotas do admin exigem token de administrador com permissão no módulo (#4, #5); rotas `/conta` exigem cliente logado.

```
POST /auth/login                       (público)
{ "email": "admin@aeria.com.br", "senha": "aeria123" }
-> 200 { "token": "eyJ...", "expiraEm": "2026-10-14T20:00:00",
         "usuario": { "id": 1, "nome": "Administrador", "email": "admin@aeria.com.br" },
         "perfis": ["ADMINISTRATIVO"] }
-> 401 Problem /errors/unauthorized   e-mail ou senha errados, ou usuário inativo
       (mesma mensagem nos dois casos; nunca diz qual campo errou)
-> 400 errors[].field = "email" | "senha"   campo vazio
   O e-mail é comparado sem diferenciar maiúsculas.
   Login por CPF/CNPJ no campo email -> 401 (D1)

GET /auth/me                           (qualquer usuário logado)
-> 200 { "id": 1, "nome": "...", "email": "...", "perfis": ["ADMINISTRATIVO"] }
-> 401 sem token ou token inválido

POST /auth/logout                      -> 204

Rotas do admin (ex.: GET /marcas, POST /produtos)
-> 401 sem token
-> 403 Problem /errors/forbidden   token de usuário sem perfil administrativo

Nenhuma resposta traz senha nem senhaHash.
```
