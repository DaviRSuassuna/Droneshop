### O que entregar

Reserva por produto (kit: uma reserva por componente, D7), ligada ao item do carrinho, com `expiraEm = agora + aeria.reserva.minutos` (padrão 15). Disponível = físico - reservas ATIVA. Pagamento aprovado confirma (a #27 chama isso); a rotina `expirar-reservas` (D33) expira as vencidas e devolve o saldo. Kit reserva cada componente, nunca a si mesmo. No `%test`, `quarkus.scheduler.enabled=false`: os testes disparam a rotina pela rota.

### Contrato de API

Convenções gerais (paginação, `idXxx`, status `{id, nome}`, erros Problem) em [`docs/API.md`](https://github.com/DaviRSuassuna/droneshop/blob/develop/docs/API.md). Rotas do admin exigem token de administrador com permissão no módulo (#4, #5); rotas `/conta` exigem cliente logado.

```
POST /carrinho/reservar   (header X-Carrinho-Token; feito ao entrar no checkout)
-> 200 carrinho, cada item com "reservas": [ { "id","produto":{"id"},"quantidade","status":{...},"expiraEm" } ]
   repetir renova o expiraEm, não duplica
-> 409 /errors/conflict  algum item acima do disponível (RN01); nada é reservado

GET /status-reserva -> 200 [ ATIVA=1, CONFIRMADA=2, EXPIRADA=3 ]
GET /estoque/reservas?idProduto=&page=&pageSize= -> 200 PageResponse (só ATIVA)   (admin)

POST /admin/rotinas/expirar-reservas?referencia=2099-01-01T00:00:00   (só ADMIN)
-> 200 { "processados": 3 }   expira as ATIVA com expiraEm < referencia (padrão: agora)

Em GET /produtos/{id}: "disponivel" já desconta as reservas ATIVA
```
