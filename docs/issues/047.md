### O que entregar

Login pelo botão do Google Identity Services: o front recebe o ID token e manda ao backend, que valida no Google (`GoogleClient`, `quarkus.rest-client.google.url`, endpoint `tokeninfo`) (D37). Identificador é o `sub`. Conta nova só-Google não tem senha; conta local com o mesmo e-mail verificado é vinculada. No `%test`, `GoogleFalso` aceita ID token no formato `sub|email` (D34).

### Contrato de API

Convenções gerais (paginação, `idXxx`, status `{id, nome}`, erros Problem) em [`docs/API.md`](https://github.com/DaviRSuassuna/droneshop/blob/develop/docs/API.md). Rotas do admin exigem token de administrador com permissão no módulo (#4, #5); rotas `/conta` exigem cliente logado.

```
POST /auth/google { "idToken": "..." }
-> 200 mesmo corpo do /auth/login ; cria Usuario + PerfilCliente + ContaSocial se não existir
-> 401 ID token inválido ou e-mail não verificado no Google
GET /provedores-social -> 200 [ GOOGLE=1 ]
GET /conta/contas-sociais -> 200 [ { "provedor":{...},"dataCadastro" } ]
Usuário só-Google: PUT /conta/senha responde 400 field "senhaAtual" (não tem senha);
POST /auth/recuperar-senha não envia e-mail (#33)
```
