### O que entregar

Tokens de uso único com expiração (24 h para verificação, 1 h para senha), enviados por e-mail (`VERIFICAR_EMAIL`, `RECUPERAR_SENHA`). Recuperação só para quem tem senha local. O e-mail traz um link com `?token=<token>` (o token só tem letras, números, `-` e `_`). Também entra aqui o convite do usuário administrativo (D35): criar usuário pelo admin envia link para definir a senha.

### Contrato de API

Convenções gerais (paginação, `idXxx`, status `{id, nome}`, erros Problem) em [`docs/API.md`](https://github.com/DaviRSuassuna/droneshop/blob/develop/docs/API.md). Rotas do admin exigem token de administrador com permissão no módulo (#4, #5); rotas `/conta` exigem cliente logado.

```
POST /auth/verificar-email/enviar  (logado) -> 204   envia o e-mail com o token
POST /auth/verificar-email { "token": "..." } -> 204 ; usuário fica emailVerificado = true
-> 400 errors[].field = "token"   inválido, expirado ou já usado

POST /auth/recuperar-senha { "email": "..." } -> 204 sempre (não revela se o e-mail existe)
   conta só-Google não recebe e-mail
POST /auth/redefinir-senha { "token": "...", "senhaNova": "..." } -> 204
-> 400 errors[].field = "token" | "senhaNova"
   Redefinir revoga todas as sessões do usuário.
```
