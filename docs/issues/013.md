### O que entregar

Toda alteração de estoque gera movimento (ENTRADA, SAIDA, AJUSTE, DEVOLUCAO, PERDA) com `saldoResultante` e `origem`. `autor` só quando MANUAL. A criação da variante com saldo inicial (#9) passa a gravar um movimento ENTRADA MANUAL do usuário logado. Kit não recebe movimento: o movimento é sempre no componente.

Quantidade: ENTRADA e DEVOLUCAO somam; SAIDA e PERDA subtraem; AJUSTE recebe o **saldo novo** em `quantidade` e grava a diferença.

### Contrato de API

Convenções gerais (paginação, `idXxx`, status `{id, nome}`, erros Problem) em [`docs/API.md`](https://github.com/DaviRSuassuna/droneshop/blob/develop/docs/API.md). Rotas do admin exigem token de administrador com permissão no módulo (#4, #5); rotas `/conta` exigem cliente logado.

```
GET /tipos-movimento   -> 200 [ ENTRADA=1, SAIDA=2, AJUSTE=3, DEVOLUCAO=4, PERDA=5 ]
GET /origens-registro   -> 200 [ MANUAL=1, SISTEMA=2, INTEGRACAO=3 ]

POST /estoque/movimentos
{ "idVariante": 31, "idTipo": 1, "quantidade": 5, "observacao": "NF 123" }
-> 200 { "id": 90, "tipo": {...}, "origem": {"id":1,"nome":"MANUAL"},
         "quantidade": 5, "saldoResultante": 15, "observacao": "NF 123",
         "autor": {"id":1,"nome":"Administrador"}, "dataCadastro": "...",
         "variante": {"id":31,"sku":"...","nome":"..."} }
-> 400 errors[].field = "quantidade"   menor que 1 (exceto AJUSTE, que aceita 0)
-> 409 /errors/conflict               SAIDA ou PERDA deixaria o saldo negativo
-> 400 errors[].field = "idVariante"  variante kit (movimento é no componente)
-> 404 variante inexistente
   Pela API o movimento é sempre MANUAL, com o usuário do token como autor.

GET /estoque/movimentos?idVariante=&idTipo=&page=&pageSize=  -> 200 PageResponse, mais recente primeiro
GET /estoque?situacao=&busca=&page=&pageSize=
-> 200 PageResponse de { "variante": {...}, "produto": {...}, "estoqueFisico", "reservado",
                         "disponivel", "estoqueMinimo", "abaixoDoMinimo": true|false }
   situacao = ABAIXO_MINIMO | ZERADO | TODOS (padrão)
```
