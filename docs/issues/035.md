pedido

### Diagrama de referência

### Requisitos, regras e decisões (PRD)

RF29, D3, D31

### O que entregar

`emitir()` gera número sequencial por série (texto só com dígitos, sem pular), série `1` e chave de acesso fictícia de 44 dígitos com dígito verificador (módulo 11); XML e DANFE (PDF simples) gerados localmente e servidos pela API. Sem SEFAZ nem certificado (D3). Nota de venda: pedido PAGO ou depois; nota de devolução: emitida pela #37.

### Contrato de API

Convenções gerais (paginação, `idXxx`, status `{id, nome}`, erros Problem) em [`docs/API.md`](https://github.com/DaviRSuassuna/droneshop/blob/develop/docs/API.md). Rotas do admin exigem token de administrador com permissão no módulo (#4, #5); rotas `/conta` exigem cliente logado.

```
GET /tipos-origem-nota -> 200 [ VENDA=1, DEVOLUCAO=2 ]
POST /pedidos/{id}/nota-fiscal -> 200 { "id","tipoOrigem":{"id":1,...},"numero","serie":"1",
                                        "chaveAcesso":"44 dígitos","xmlUrl","danfeUrl","dataEmissao" }
-> 409 pedido PENDENTE ou CANCELADO, ou nota de venda já emitida
GET /pedidos/{id}/nota-fiscal -> 200 [ notas do pedido ]
GET {xmlUrl} -> 200 application/xml ; GET {danfeUrl} -> 200 application/pdf
GET /conta/pedidos/{id}/nota-fiscal (dono) -> 200 [ ... ]
```
