### O que entregar

Criação de conta do cliente e perfil 0..1 do usuário com `tipoPessoa`, `nome`, `documento` e `telefone`. Endereços reaproveitam o módulo `endereco` (CEP pelo ViaCEP, município por `idMunicipio`, D32). Documento, telefone e CEP só com dígitos: a API aceita com máscara e guarda sem. O `id` devolvido na criação da conta é o id do **usuário** (o mesmo de `/auth/me`).

### Contrato de API

Convenções gerais (paginação, `idXxx`, status `{id, nome}`, erros Problem) em [`docs/API.md`](https://github.com/DaviRSuassuna/droneshop/blob/develop/docs/API.md). Rotas do admin exigem token de administrador com permissão no módulo (#4, #5); rotas `/conta` exigem cliente logado.

```
GET /tipos-pessoa -> 200 [ PF=1, PJ=2 ]

POST /clientes   (público: criar conta)
{ "nome": "Ana Lima", "email": "ana@exemplo.com", "senha": "segredo123",
  "idTipoPessoa": 1, "documento": "52998224725", "telefone": "63999990000" }
-> 200 { "id": 20, "nome", "email", "tipoPessoa": {...}, "documento", "telefone" }
-> 400 errors[].field = "documento"  CPF inválido para PF, CNPJ inválido para PJ (util/Documentos), ou já usado
-> 400 errors[].field = "email"      inválido ou já usado
-> 400 errors[].field = "senha"      menos de 8 caracteres
   Depois disso, POST /auth/login devolve "perfis": ["CLIENTE"].

GET /conta/perfil  (cliente logado) -> 200 { "nome", "email", "tipoPessoa", "documento", "telefone" }
PUT /conta/perfil  { "nome", "telefone" } -> 204   (documento e tipo não mudam)
PUT /conta/senha   { "senhaAtual", "senhaNova" } -> 204 | 400 field "senhaAtual"

GET  /conta/enderecos -> 200 [ { "id", "apelido", "cep", "logradouro", "numero", "complemento",
                                  "bairro", "municipio": {"id","nome","estado":{"sigla"}}, "principal" } ]
POST /conta/enderecos { "apelido": "Casa", "cep": "77001000", "logradouro": "...", "numero": "10",
                        "complemento": "", "bairro": "...", "idMunicipio": 1, "principal": true }
-> 200 endereço ; o primeiro endereço é sempre principal
-> 400 errors[].field = "cep" | "idMunicipio" | "logradouro" | "numero"
PUT /conta/enderecos/{id} -> 204 ; DELETE -> 204 (principal excluído passa a vez ao mais antigo)
PATCH /conta/enderecos/{id}/principal -> 204   (desmarca o anterior)
Endereço de outro cliente -> 404

Rotas /conta sem token -> 401 ; token só de admin -> 403
```
